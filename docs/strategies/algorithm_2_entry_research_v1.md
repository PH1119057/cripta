# Algorithm 2 — Entry Research V1 (P28)

Цель этого прохода — измерить **качество точки входа отдельно от логики выхода**.
Live-стратегия и управление реальной позицией в P28 не меняются.

## Базовая гипотеза

1. Часовой канал задаёт крупную зону поддержки/сопротивления.
2. Пятиминутный канал задаёт локальную зону входа.
3. LONG-кандидат существует только когда 5m support близок к 1H support.
4. SHORT-кандидат существует только когда 5m resistance близок к 1H resistance.
5. Ромбик ChartPrime не ожидается.
6. Зоны вычисляются только по уже закрытым свечам до начала текущей 5m свечи.
7. Если текущая 5m свеча касается заранее известной границы зоны, фиксируется исследовательский Entry.
8. Выход не моделируется. Вместо него измеряются MFE/MAE и достижение +0.5/+1/+2/+3/+5% на горизонтах 30/60/120/240 минут.

Так мы не смешиваем качество Entry с качеством trailing/TP/BE.

## Два варианта зоны

`fixed` — исходная идея ChartPrime: максимум/минимум последних 130 свечей.

`adaptive` — тот же максимум/минимум, но после аномально большой свечи старый диапазон может быть отброшен. Аномалия определяется каузально относительно предыдущей волатильности. Этот режим сделан отдельным вариантом, чтобы сравнивать его с fixed, а не верить ему заранее.

## Запуск на Windows

```powershell
cd C:\cripta
powershell -ExecutionPolicy Bypass -File .\scripts\research_mtf_entry_windows.ps1 -Symbol UNIUSDT -Days 30 -Variant fixed
```

После первого результата:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\research_mtf_entry_windows.ps1 -Symbol UNIUSDT -Days 30 -Variant adaptive
```

Отчёты создаются в `reports\entry_research\...`:

- `summary.json` — агрегированная статистика;
- `signals.csv` — каждая точка входа и её последующее движение;
- `trade_5m.csv`, `trade_60m.csv` — исходные свечи Bybit, использованные в проходе.

## Что пока намеренно НЕ входит

- taker Buy/Sell delta / CVD;
- Open Interest;
- стакан/imbalance/absorption;
- RSI/MACD;
- новая логика Break Even, trailing и динамического Take Profit.

Каждый из этих слоёв должен добавляться после отдельного baseline, чтобы было видно, улучшил он вход или ухудшил.
