# Алгоритм 1 — Trend Breakout Retest

Статус: согласованная спецификация v0.1 для реализации и исторической проверки.  
Strategy ID: `user_algorithm_1`.  
Текущая версия реализации: `0.2.0`.  

Это проверяемая торговая гипотеза, а не обещание доходности. Значения по умолчанию
являются первой контрольной конфигурацией и не считаются оптимальными.

## 1. Назначение

Алгоритм ищет закрытие за пределами причинного ценового канала, но не преследует
цену рыночной заявкой. После пробоя он выставляет ограниченную по времени лимитную
заявку на ретест пробитой границы. Такая семантика соответствует текущему безопасному
Mainnet execution-контуру, который разрешает обычный вход только GTC-limit заявкой.

V0.1 работает на одном символе и одном таймфрейме за запуск. Мультитаймфреймовый
фильтр и автоматическое переключение режимов не входят в эту версию.

## 2. Данные и причинность

- Используются только закрытые OHLCV-свечи выбранного таймфрейма.
- Сигнал свечи `t` использует канал только из свечей `t-N ... t-1`; сама свеча
  `t` в границы, относительно которых проверяется пробой, не входит.
- Решение после закрытия `t` не может исполниться раньше свечи `t+1`.
- Незакрытая свеча никогда не меняет сигнал.
- После создания сигнала снимок канала и ATR фиксируется и не пересчитывается.
- Все вычисления выполняются через `Decimal`.

Истинный диапазон:

```text
TR[t] = max(
  high[t] - low[t],
  abs(high[t] - close[t-1]),
  abs(low[t] - close[t-1])
)
```

ATR рассчитывается по Wilder RMA. Первое значение — простое среднее первых
`atr_period` значений TR; далее:

```text
ATR[t] = (ATR[t-1] * (atr_period - 1) + TR[t]) / atr_period
```

Канал перед проверкой свечи `t`:

```text
upper[t] = max(high[t-entry_lookback : t])
lower[t] = min(low[t-entry_lookback : t])
```

Правая граница среза не включается.

## 3. Параметры v0.1

| Параметр | Тип | По умолчанию | Допустимо | Смысл |
| --- | --- | ---: | ---: | --- |
| `entry_lookback` | int | 55 | 20..200 | Длина причинного канала |
| `atr_period` | int | 20 | 5..100 | Период Wilder ATR |
| `initial_stop_atr` | Decimal | 2.0 | 0.5..10 | Начальная stop-дистанция |
| `trailing_stop_atr` | Decimal | 3.0 | 0.5..15 | Chandelier trailing |
| `entry_valid_bars` | int | 2 | 1..10 | Срок жизни limit entry |
| `cooldown_bars` | int | 1 | 0..100 | Пауза после закрытия сделки |
| `requested_leverage` | Decimal | 1 | 1..10 | Запрос стратегии; Risk Gate может только уменьшить/запретить |
| `direction_mode` | text | `both` | `long`, `short`, `both` | Разрешённые направления стратегии |
| `take_profit_r` | Decimal | 0 | 0..20 | 0 отключает фиксированный TP |
| `exit_on_opposite_breakout` | bool | true | true/false | Выход без немедленного разворота |

Типы, диапазоны и отношения параметров валидируются до запуска. Неизвестный параметр
является ошибкой, а не игнорируется.

Минимальный прогрев для конкретного набора параметров:

```text
max(entry_lookback + 1, atr_period + 2)
```

До завершения прогрева стратегия возвращает диагностический `NoOpIntent` и не создаёт
торговых намерений.

## 4. Машина состояний

```text
WARMUP -> FLAT -> ENTRY_PENDING -> LONG/SHORT -> COOLDOWN -> FLAT
```

- Одновременно допустим только один кандидат, один pending entry или одна позиция.
- Пирамидинг, усреднение и разворот в той же свече запрещены.
- Состояние, снимок сигнала и счётчик срока заявки должны сериализоваться и
  восстанавливаться после перезапуска.
- Локальное состояние сверяется с биржевой позицией и заявкой; биржа является
  источником истины.

## 5. Правила входа

Стратегия рассматривает вход только если позиция flat, pending entry отсутствует,
cooldown завершён и Risk/health контуры допускают новые входы.

### Long

После закрытия свечи `t`:

```text
close[t] > upper[t]
```

При строгом выполнении условия создаётся снимок:

- `signal_bar_closed_at`;
- `upper`, `lower`, `ATR`;
- OHLCV сигнальной свечи;
- версия стратегии и параметры.

Создаётся `EnterIntent`:

```text
direction   = Long
order_type  = Limit
entry_price = upper[t]
stop_price  = entry_price - initial_stop_atr * ATR[t]
```

Если `take_profit_r > 0`:

```text
R = entry_price - stop_price
take_profit = entry_price + take_profit_r * R
```

### Short

Зеркальные правила:

```text
close[t] < lower[t]
entry_price = lower[t]
stop_price  = entry_price + initial_stop_atr * ATR[t]
take_profit = entry_price - take_profit_r * R  # если включён
```

High/low, пересёкшие канал внутри свечи без закрытия за его пределами, сигнала не дают.
Равенство границе также не является пробоем.

## 6. Pending entry

- Заявка действует не более `entry_valid_bars` полностью закрытых свечей после
  сигнальной.
- После истечения срока создаётся ровно один `CancelEntryIntent`.
- Частичное исполнение означает открытую позицию; неисполненный остаток отменяется,
  а защита пересчитывается на фактически подтверждённое количество.
- Risk rejection, exchange rejection и отмена должны передаваться стратегии явным
  результатом intent/order, а не восстанавливаться догадкой.
- Повторная генерация того же сигнала после рестарта запрещена детерминированным
  `intent_id` длиной не более 36 символов.

Текущая GTC-limit модель означает: сильный пробой без ретеста будет сознательно
пропущен. Нельзя считать такой пропуск ошибкой или дорисовывать исполнение в BackTest.

## 7. Сопровождение позиции

После подтверждённого исполнения сохраняются `highest_since_entry` для Long или
`lowest_since_entry` для Short.

На каждой следующей закрытой свече:

```text
Long candidate  = highest_since_entry - trailing_stop_atr * ATR[t]
Long new_stop   = max(current_confirmed_stop, candidate)

Short candidate = lowest_since_entry + trailing_stop_atr * ATR[t]
Short new_stop  = min(current_confirmed_stop, candidate)
```

`UpdateProtectionIntent` создаётся только если нормализованная по tick size граница
реально улучшает защиту. Stop никогда не расширяет риск. Биржевой hard stop остаётся
обязательным даже при клиентском trailing.

Если `exit_on_opposite_breakout=true`, позиция закрывается `ExitIntent` после
закрытого противоположного пробоя. Немедленный вход в обратную сторону запрещён;
сначала должен завершиться cooldown.

При потере данных или связи новые намерения не создаются. Уже подтверждённый серверный
stop не снимается.

## 8. Golden examples

### Long signal

Для учебного `entry_lookback=5` предыдущие high равны `100, 102, 101, 103, 104`.
Значит `upper=104`. Сигнальная свеча закрылась по `105.2`, ATR равен `2`,
`initial_stop_atr=2`.

Ожидается один Long limit:

```text
entry = 104
stop  = 100
```

Он может исполниться только начиная со следующей свечи и только если её диапазон
достигает 104 с учётом правил Replay.

### Нет сигнала

При том же `upper=104` свеча имела high `106`, но close `103.9`. Намерение не
создаётся: внутрисвечной прокол не считается пробоем.

### Монотонный trailing

Long: подтверждённый stop `100`, highest since entry `110`, ATR `2`, multiplier `3`.
Кандидат равен `104`, значит stop переносится на `104`. Если позже кандидат станет
`103`, обновление не создаётся и stop остаётся `104`.

## 9. Обязательные counterexamples

- Канал, случайно включающий сигнальную свечу.
- Сигнал по незакрытой свече.
- Исполнение в сигнальной свече.
- Повторный intent после рестарта или дубликата свечи.
- Два pending entry одновременно.
- Long stop, сдвинутый вниз, или Short stop, сдвинутый вверх.
- Автоматический разворот позиции в одной свече.
- «Исполненный» limit, которого цена следующей свечи не достигала.

## 10. Первые BackTest-эксперименты

Каждый символ и таймфрейм проверяется отдельным отчётом. Начать с таймфреймов `60`
и `240`; это исследовательская отправная точка, а не утверждение, что они лучшие.

Сначала прогнать ровно конфигурацию по умолчанию. Затем выполнять ограниченную
чувствительность по одному параметру за раз; финальный test-период не используется
для выбора параметров. Historical gate разрешает Micro-Live только для точного
fingerprint версии и параметров, прошедших проверку в исполнимом limit-retest режиме.
