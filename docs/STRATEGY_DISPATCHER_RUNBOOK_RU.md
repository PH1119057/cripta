**Принцип:** весь D0–D6 можно подготовить без изменения торгового контура.

# D0 — архитектура и словарь

**Статус кода:** подготовлено.

- архитектурный контракт;
- словарь рыночной среды;
- ссылка в `AGENTS.md`;
- разделение `Маяк -> Диспетчер -> потребитель`.

Торгового эффекта нет.

# D1 — чистое ядро

**Статус кода:** подготовлено.

Пакет `strategy_dispatcher` содержит чистые контракты и движок сопоставления.
Он не импортирует:

- Entry/strategies;
- Exit;
- Risk;
- Execution;
- Position Supervisor;

# D2 — профили и детерминированная оценка

**Статус кода:** подготовлено.

Поддерживаются:

- REQUIRED;
- PREFERRED;
- TOLERATED;
- REJECTED;
- hard conflict;
- fail-closed на missing required;
- suitability 0..1;
- confidence 0..1;
- объяснение каждого правила;
- version-aware registry;
- детерминированный assessment id.

# D3 — read-only адаптер Маяка

**Статус кода:** подготовлено.

Модуль `adapter.py` поддерживает два режима.

## Канонический режим

Будущий/новый Маяк предпочтительно публикует отдельный строгий объект
`dispatcher_handoff` внутри своего диагностического снимка:

```json
{
  "state": "любые внутренние поля Маяка остаются снаружи",
  "dispatcher_handoff": {
  "observed_at": "...",
  "snapshot_id": "...",
  "architecture_version": "...",
  "engine_version": "...",
  "data_quality": "HIGH",
  "dispatcher_features": {
    "market.direction": {
      "value": "DOWN",
      "status": "VALID",
      "confidence": 0.94,
      "observed_at": "..."
    }
  }
  }
}
```

Строгая JSON-схема относится именно к объекту `dispatcher_handoff`.
Адаптер переносит эти признаки в контракт Диспетчера и не анализирует сделки,
позиции либо PnL.

## Legacy bridge

Для слепка 2026-08-29 поддерживается старый `mayak_v2/status.json`.

Legacy bridge:

- нужен только для совместимости/replay;
- переносит ограниченный набор непосредственно наблюдаемых полей;
- не придумывает ликвидации, события и недоступные признаки;
- **жёстко ограничивает global quality значением LOW**.

Это сделано специально: старый снимок Маяка не должен случайно стать
production-grade основанием для профиля, требующего HIGH quality.

# D4 — пассивный сервис и хранение

**Статус кода:** подготовлено, но НЕ включено.

`PassiveDispatcherService`:

1. читает файл снимка Маяка;
2. адаптирует его;
3. загружает только профили с `enabled=true`;
4. рассчитывает оценки;
5. пишет:
   - `status.json` атомарно;
   - `assessments.jsonl` append-only.

По умолчанию runtime paths:

```text
Mayak input:
/var/lib/cripta/mayak_v2/status.json

Profiles:
/srv/cripta/config/strategy_dispatcher/profiles

Dispatcher state:
/var/lib/cripta/strategy_dispatcher
```

В payload есть hardening-шаблон systemd unit, но установщик:

- не копирует его в `/etc`;
- не делает `daemon-reload`;
- не enable;
- не start/restart.

Все reference profiles поставляются `enabled=false`.

# D5 — versioned profiles + replay

**Статус кода:** подготовлено.

Реализованы:

- строгая загрузка профилей из JSON;
- versioned profile contract;
- offline replay JSONL снимков Маяка;
- отдельный JSONL output assessments;
- summary по статусам пригодности.

Поставляются только reference profiles:

- спокойная консервативная среда;
- пробойная среда;
- истощение/отскок.

Они являются примерами формы контракта и **не являются подтверждёнными live
правилами**.

Trade outcomes не используются в live assessment.

# D6 — интерфейс потребителя

**Статус кода:** подготовлен только интерфейс, торговый контур НЕ подключён.

`FileDispatcherContextProvider` позволяет будущему потребителю получить последнюю
оценку по:

```text
profile_id + profile_version
```

Это read-only интерфейс.

На данном этапе запрещено изменять существующие стратегии так, чтобы они начали его
использовать.

Таким образом D6 завершает программный контракт, но не является торговой
интеграцией.

# Что остаётся после установки D0–D6

Это уже не написание ядра Диспетчера, а интеграционная работа на свежем сервере:

1. завершить новую каноническую форму Маяка;
2. сопоставить реальные поля Маяка со stable feature ids;
3. прогнать текущие Ruff/mypy/full pytest;
4. при желании вручную установить systemd unit;
5. отдельно включить только исследовательские SHADOW profiles;
6. накопить историю;
7. только после evidence создавать версии профилей реальных стратегий;
8. только отдельным решением подключать конкретную стратегию как потребителя.

# Неподвижная граница безопасности

Даже после D6:

```text
Маяк -> Диспетчер -> стратегия
```

Диспетчер не имеет обратной связи к Маяку и не имеет прямого пути к Execution.

Диспетчер сам никогда не торгует.
