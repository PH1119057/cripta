# ДИСПЕТЧЕР СТРАТЕГИЙ — СПРАВОЧНИК ПРОФИЛЕЙ РЫНОЧНОЙ СРЕДЫ

**Версия:** 1.0  
**Назначение:** единые правила описания того, какой внешний рынок нужен торговой стратегии.

# 1. Что такое профиль

Профиль рыночной среды — это не стратегия и не Entry.

Он отвечает только:

> какие свойства внешнего рынка совместимы с нормальной работой этой стратегии?

Пример:

```text
Стратегия знает, КАК входить.
Профиль знает, В КАКОМ МОРЕ этой стратегии имеет смысл искать вход.
```

# 2. Что нельзя помещать в профиль

Запрещены условия вида:

- цена коснулась нашей зоны;
- появился exact-touch;
- наш Entry дал LONG;
- позиция уже -0,4%;
- наш stop находится на таком-то уровне;
- предыдущая сделка была убыточной;
- баланс счёта такой-то;
- увеличить плечо;
- закрыть позицию.

Это не свойства внешнего рынка.

# 3. Что можно помещать в профиль

Только характеристики из канонического словаря Диспетчера.

Например:

- качество данных;
- волатильность;
- направление;
- устойчивость движения;
- ширина рынка;
- синхронность;
- денежное давление;
- OI;
- ликвидность;
- поглощение;
- фаза ликвидаций;
- хаотичность;
- стабильность режима;
- состояние BTC/ETH;
- событийный фон.

# 4. Четыре типа требования

## REQUIRED — обязательно

Без признака либо без совпадения среда не считается доказанно подходящей.

Пример:

```json
{
  "feature_id": "data.quality",
  "mode": "REQUIRED",
  "operator": "ONE_OF",
  "expected": ["HIGH"]
}
```

## PREFERRED — желательно

Совпадение увеличивает пригодность среды, отсутствие совпадения само по себе не
запрещает её.

## TOLERATED — допустимо

Условие считается приемлемым, но имеет меньший положительный вес.

## REJECTED — противоречит профилю

Если такой фактор присутствует, профиль получает hard conflict независимо от
мягкого итогового балла.

# 5. REQUIRED не должен использоваться без необходимости

Ошибка:

> превратить каждый хороший исторический признак в обязательный hard gate.

Это быстро создаст профиль, который почти никогда не разрешает рынок.

REQUIRED оправдан, когда отсутствие признака действительно делает оценку
невалидной.

Например качество обязательного источника.

# 6. REJECTED тоже требует доказательства

REJECTED означает архитектурно сильное утверждение:

> эта среда несовместима с логикой стратегии.

Его нельзя добавлять только потому, что несколько прошлых сделок оказались
убыточными.

Сначала research, затем новая версия профиля.

# 7. Версия профиля

Любое изменение набора правил создаёт новую версию.

```text
CONSERVATIVE_MARKET_PROFILE 1.0
CONSERVATIVE_MARKET_PROFILE 1.1
CONSERVATIVE_MARKET_PROFILE 2.0
```

Старые оценки не переписываются.

# 8. Один профиль не обязан использовать весь словарь

Если стратегии безразлично funding, она его не указывает.

Если новая версия Маяка добавила новый показатель, существующие профили не должны
самопроизвольно менять поведение.

# 9. Отсутствующий обязательный признак

Если REQUIRED feature отсутствует либо имеет:

```text
WARMUP
STALE
NO_DATA
ERROR
```

результат:

```text
INSUFFICIENT_DATA
```

а не «условие не подтвердилось» и не «нейтрально».

# 10. Плохое глобальное качество данных

Даже если отдельное поле похоже на подходящее, глобальный статус:

```text
INSUFFICIENT
```

не позволяет публиковать обычную пригодность.

# 11. Балл не заменяет hard conflict

Пример:

```text
мягкие признаки: 95% совпадения
REJECTED liquidation.phase = CASCADE: сработал
```

Результат:

```text
INCOMPATIBLE
```

а не 95% пригодности.

# 12. Направление и тип торговли разделяются

Профиль может описывать:

```text
TREND_FOLLOWING
```

без встроенного LONG/SHORT.

Маяк отдельно сообщает направление рынка.

Конкретная стратегия сама определяет, как использовать направление.

При необходимости допускаются отдельные профили:

```text
BREAKOUT_UP
BREAKOUT_DOWN
```

но это уже осознанное свойство конкретного профиля.

# 13. Пример спокойной стратегии

Это только форма, не утверждённые параметры:

```text
REQUIRED:
  quality = HIGH

PREFERRED:
  volatility = LOW/NORMAL
  synchronization = LOW/NORMAL
  regime_stability = HIGH

REJECTED:
  liquidation_phase = CASCADE
  chaos = EXTREME
```

# 14. Пример пробойной стратегии

```text
REQUIRED:
  quality = HIGH

PREFERRED:
  breakout_environment = FAVORABLE/STRONG
  direction_strength = STRONG/EXTREME
  continuation_environment = FAVORABLE/STRONG
```

Направление сделки остаётся логикой стратегии.

# 15. Пример стратегии истощения

```text
REQUIRED:
  quality = HIGH

PREFERRED:
  liquidation_phase = EXHAUSTION/RECOVERY
  exhaustion = STRONG/CONFIRMED
  bounce_environment = FAVORABLE/STRONG

REJECTED:
  liquidation_acceleration = SURGING
```

# 16. Нельзя обучать live-профиль на каждой новой сделке

Запрещён цикл:

```text
проиграли -> автоматически поменяли профиль -> продолжили live
```

Правильно:

```text
результаты -> отдельное research -> новая версия профиля -> SHADOW -> решение
```

# 17. Профиль конкретной стратегии и класс торговли

В будущем можно иметь два уровня:

```text
КЛАСС СРЕДЫ:
BREAKOUT

КОНКРЕТНЫЙ ПРОФИЛЬ:
BREAKOUT_ENTRY_V3_MARKET_PROFILE_1.2
```

Но ядро Диспетчера не должно содержать фиксированный закрытый список классов.

# 18. Шаблон

Машинный шаблон находится в:

```text
config/strategy_dispatcher/PROFILE_TEMPLATE_RU.json
```

Схема:

```text
config/strategy_dispatcher/PROFILE_SCHEMA_V1.json
```

Канонический словарь:

```text
config/strategy_dispatcher/vocabulary_v1.json
```

# 19. Правило добавления новой стратегии

Нормальный процесс:

1. Entry/Exit/Risk стратегии разрабатываются отдельно.
2. Определяется, какой внешний рынок ей нужен.
3. Создаётся новый versioned market profile.
4. Профиль проходит replay.
5. Профиль проходит SHADOW.
6. Только затем стратегия может отдельно решить использовать оценку Диспетчера.

Ни Маяк, ни ядро Диспетчера при этом не меняются.

# 20. Главный тест качества профиля

Нужно спросить:

> если полностью удалить из системы торгового бота, каждое ли условие этого профиля
> всё ещё описывает внешний рынок?

Если нет — правило находится не в том слое.
