# ДИСПЕТЧЕР СТРАТЕГИЙ — АРХИТЕКТУРНЫЙ КОНТРАКТ

**Документ:** `STRATEGY_DISPATCHER_ARCHITECTURE_RU.md`  
**Версия:** 1.0  
**Статус:** архитектурный контракт нового пассивного слоя  
**Зависимость:** канонический контракт `MAYAK_ARCHITECTURE_PRINCIPLES_RU.md`

## 1. Назначение

Диспетчер стратегий — независимый слой между Маяком и торговыми стратегиями.

Он отвечает только на вопрос:

> **Для каких типов торговли текущая внешняя рыночная среда подходит лучше, хуже или пока неопределённа?**

Он не отвечает на вопросы «что купить», «что продать», «войти ли сейчас», «где поставить стоп».

## 2. Архитектурная цепочка

```text
ВНЕШНИЙ РЫНОК
      ↓
    МАЯК
      ↓
объективный причинный снимок рынка
      ↓
ДИСПЕТЧЕР СТРАТЕГИЙ
      ↓
оценка соответствия рынка профилям
      ↓
ТОРГОВЫЕ СТРАТЕГИИ
      ↓
Entry / Risk / Exit / Execution
```

Обратной стрелки от Диспетчера к Маяку нет.

## 3. Граница Маяка

Диспетчер не изменяет:

- источники Маяка;
- признаки Маяка;
- состояния Маяка;
- пороги Маяка;
- качество данных Маяка;
- исторические снимки Маяка.

Один и тот же снимок Маяка должен быть одинаковым независимо от количества профилей и стратегий в Диспетчере.

## 4. Граница торговли

Диспетчер не имеет права:

- размещать, отменять или изменять ордера;
- запрещать или разрешать Entry;
- закрывать позиции;
- менять стоп или тейк;
- менять размер позиции, плечо или риск;
- обращаться к приватному торговому API;
- принимать владение сделкой после fill.

Его результат — только объект оценки пригодности среды.

## 5. Почему нужен отдельный слой

Без Диспетчера каждая стратегия начнёт заново реализовывать собственные версии понятий:

- тренд;
- боковик;
- пробой;
- волатильность;
- синхронность;
- истощение;
- ликвидационный каскад;
- качество ликвидности.

Это создаст несколько несовместимых «маленьких Маяков» внутри стратегий.

Диспетчер должен дать всем стратегиям единый стабильный язык торговой среды.

## 6. Два входа Диспетчера

Диспетчер принимает только:

1. `DispatcherMarketSnapshot` — адаптированное представление причинного снимка Маяка.
2. `StrategyMarketProfile` — версионированное описание того, какая среда нужна потребителю.

Формула:

```text
MAYAK SNAPSHOT
      +
MARKET PROFILE
      ↓
DISPATCHER ASSESSMENT
```

## 7. Профиль рынка — не Entry

Профиль не содержит:

- уровней поддержки/сопротивления;
- exact-touch;
- лимитной цены;
- размера позиции;
- стопа;
- TP;
- конкретного сигнала монеты.

Он описывает только требуемую внешнюю среду.

## 8. Неограниченное количество стратегий

Диспетчер не содержит закрытого перечня стратегий.

Новая стратегия добавляет новый профиль либо переиспользует существующий класс среды. Ядро Диспетчера не должно меняться из-за появления новой стратегии.

## 9. Виды правил профиля

### REQUIRED — обязательно
Если обязательный признак отсутствует, результат `INSUFFICIENT_DATA`.
Если он есть, но не соответствует профилю, профиль несовместим.

### PREFERRED — предпочтительно
Соответствие повышает оценку пригодности.

### TOLERATED — допустимо
Соответствие допустимо, но слабее влияет на оценку.

### REJECTED — противоречит профилю
Если запрещённая среда присутствует, результат `INCOMPATIBLE` независимо от высокого мягкого балла.

## 10. Hard conflict важнее среднего балла

Нельзя получить:

```text
score = 0.91
GOOD_MATCH
```

если профиль явно запрещает `LIQUIDATION_PHASE = CASCADE`, а текущий рынок находится в каскаде.

## 11. Отсутствие данных

`NO_DATA`, `STALE`, `WARMUP`, `ERROR` не равны нейтральному состоянию.

Если отсутствует REQUIRED-признак, Диспетчер обязан ответить:

`INSUFFICIENT_DATA`.

## 12. Детерминированность

Одинаковые:

- snapshot id и содержимое;
- версия профиля;
- версия Диспетчера

должны давать одинаковую оценку, включая `assessment_id`.

## 13. Версионирование

Каждая оценка хранит минимум:

- `dispatcher_version`;
- `mayak_version`;
- `architecture_version` Маяка;
- `profile_id`;
- `profile_version`;
- `snapshot_id`.

Изменение профиля создаёт новую версию, а не переписывает историю.

## 14. Результат оценки

Результат должен содержать:

- пригодность 0..1 либо `None`, если данных недостаточно;
- confidence 0..1;
- статус;
- совпавшие обязательные признаки;
- отсутствующие обязательные признаки;
- совпавшие предпочтительные признаки;
- противоречия;
- сработавшие запреты;
- отсутствующие факторы;
- подробную оценку каждого правила.

## 15. Статусы V1

- `EXCELLENT_MATCH`;
- `GOOD_MATCH`;
- `PARTIAL_MATCH`;
- `POOR_MATCH`;
- `INCOMPATIBLE`;
- `INSUFFICIENT_DATA`.

Это не торговые команды.

## 16. Пример

Маяк сообщает:

```text
направление: вниз
синхронность: экстремальная
ликвидации LONG: каскад
денежное давление: сильный продавец
OI: сокращается
поглощение: ещё слабое
качество данных: высокое
```

Диспетчер может получить одновременно:

```text
Спокойная среда: INCOMPATIBLE
Среда продолжения пробоя: GOOD_MATCH
Среда истощения/отскока: POOR_MATCH
```

Никакой позиции при этом не открывается.

## 17. Референсные профили

В коде разрешены демонстрационные профили для тестов архитектуры, но они:

- не регистрируются автоматически;
- не влияют на live;
- не являются исследованными торговыми правилами;
- не считаются утверждёнными профилями стратегии.

## 18. Живой режим и replay

Один engine используется для:

```text
HISTORICAL MAYAK SNAPSHOT ─┐
                           ├─> DISPATCHER ENGINE
LIVE MAYAK SNAPSHOT ───────┘
```

Исторический режим не имеет отдельной математики.

## 19. Аудит

После подключения хранения каждая оценка должна сохранять:

```text
assessment_id
timestamp
mayak_snapshot_id
dispatcher_version
profile_id
profile_version
suitability
status
confidence
positive_factors
negative_factors
missing_factors
```

## 20. Безопасность

Автоматическими тестами должно подтверждаться:

1. пакет Диспетчера не импортирует `execution`;
2. не импортирует `risk`;
3. не импортирует `position_supervisor`;
4. не импортирует торговые `strategies`;
5. не импортирует private runtime;
6. может работать при полностью выключенной торговле;
7. изменение профиля не меняет snapshot Маяка;
8. результат сделки не меняет прошлую оценку.

## 21. Главная формула

> **Маяк описывает море.**

> **Диспетчер описывает пригодность этого моря для разных типов плавания.**

> **Стратегия знает, какое море нужно ей.**

> **Торговое решение всегда остаётся в стратегии.**
