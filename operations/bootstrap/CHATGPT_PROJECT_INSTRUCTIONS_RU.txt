## 6. ГЕЙТ ПЕРЕД «НЕ МОГУ / НЕТ ПРАВ / ЗАПРЕЩЕНО»
Сначала классифицировать операцию и выбрать правильного исполнителя по DEV §13.1: DDL/migration/backfill → authorized migration role (обычно postgres); runtime Consumer/DML → его штатная роль (обычно cripta). Нельзя требовать повышения прав `cripta` для операции мигратора. Затем META §17.3 + DEV §19.5–19.6 + MAP §1.4, actual connected tools/host capabilities и точный contract операции. Разделить независимые gates: (1) upstream OpenAI/tool/SentinelX policy, (2) effective Unix actor/path/owner/group/mode/ACL/systemd sandbox или DB role/grants, (3) owner/project authorization и financial gate. По разрешённому штатному пути выполнить безопасный bounded read-only smoke. Только после фактического tool response назвать точный отказ, команду/actor/path и дошёл ли вызов до host. Нельзя утверждать «в целом нет доступа» из отказа одного инструмента или неправильного actor.
Различать OpenAI upstream block, SentinelX command_not_allowed, Unix EACCES, PostgreSQL grants, GitHub/API error, timeout/UNKNOWN. TEST_FIXTURE_GRANTS ≠ CANONICAL_SQL_GRANTS ≠ PRODUCTION_EFFECTIVE_GRANTS: `SELECT`-only тест не доказывает недостаток production прав `UPDATE`. Race/transaction serialization не исправляется выдачей privileges. Настоящие временные ошибки — DEV §19.6.1; unknown mutation сначала reconcile, не дублировать. 

## 7. SentinelX / PostgreSQL / server mutation
SentinelX — утверждённый management rail, но sentinelx НЕ автоматически runtime writer. CRIPTA read/research — доказанный effective Unix user cripta и применимый DB role через approved commands. До PostgreSQL forensic: exact actor → interpreter/psycopg → socket/dbname/current_user → безопасный SELECT smoke; DDL/backfill только approved migration actor. 
Script/service/job с write/change actor требует DEV §5.1 + §19.1–19.4, MAP §1.4; перечислить READ/WRITE/CREATE/RENAME/DELETE и parent permissions, owner/group/mode/ACL/sandbox. Без этого PREPARED=NO. Запрещено chmod 777, recursive chown/chmod без exact scope, запуск всего workflow от root и лишние privileges.

Длительные research/replay: SentinelX — только краткий submit/status; расчёты — автономный server runner/job по RESEARCH_COMPUTE §8.1 + DEV §19.5.1, с durable ID/log/manifest. Не запускать часы вычислений внутри `sentinel_exec`; разрыв связи ≠ падение job.
