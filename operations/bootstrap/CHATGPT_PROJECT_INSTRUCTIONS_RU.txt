## 2. Source of truth

Единственный authority: GitHub `PH1119057/cripta:main`.

`/srv/cripta/source_checkout` — synchronized operational mirror GitHub `main`, а не второй authority. При расхождении GitHub имеет приоритет; mirror сначала синхронизируется.

Project Source, File Library, память, старые чаты/ZIP, локальный `C:\cripta`, Git history и historical docs — только вспомогательный контекст.

Если актуальность нельзя определить однозначно:
`HARD_STOP=YES`
`OWNER_DECISION_REQUIRED=YES`
Не угадывать.

## 4. Канон и Hard Stop

Явное текущее решение владельца задаёт намерение, но не меняет канон молча.

Если запрос противоречит активному канону:
`CANON_CONFLICT=YES`
`HARD_STOP=YES`
`CANON_UPDATE_REQUIRED=YES`
`OWNER_DECISION_REQUIRED=YES`

Остановиться, назвать точный конфликт и требуемый canonical change.
После owner decision: `CANON UPDATE -> IMPLEMENTATION -> TEST -> GITHUB -> DEPLOY -> RUNTIME EVIDENCE`.

Если код расходится с каноном — это FINDING, а не разрешение автоматически менять код или архитектуру.

Если решение удаляет/ослабляет/переносит ранее требуемую capability, до implementation проверить BEFORE/AFTER owner/contract/consumer path. Нет доказанного replacement:
ARCHITECTURE_CAPABILITY_GAP=YES
HARD_STOP=YES
CANON_UPDATE_REQUIRED=YES
OWNER_DECISION_REQUIRED=YES
Не деактивировать старую capability молча.

Если термин отсутствует в `CRIPTA_GLOSSARY_RU*.md` или физически неоднозначен:
`TERM_AMBIGUOUS=YES`
`HARD_STOP=YES`
`OWNER_DECISION_REQUIRED=YES`
Не додумывать.

## 5. Research

Research любой давности — evidence, не канон.
Не наследовать автоматически старые Entry/Exit rules, thresholds, horizons, filters, Strategy parameters или defaults.
Dataset reuse != policy reuse.

Путь изменения торгового поведения:
`RESEARCH / EVIDENCE -> OWNER DECISION -> CANON / NEW STRATEGY VERSION -> TEST / SHADOW -> LIVE EQUIVALENCE -> MICRO_LIVE -> LIVE`

## 6. Текущая архитектура

Не дублировать её в Project Instructions.
Читать текущую архитектуру и ownership из ARCH / TRADING_CONTOUR / OBSERVATION_ANALYTICS / GLOSSARY / MAP.

Перед архитектурно чувствительной работой повторно проверить GitHub `main`, base pre-read и соответствующий routed contract.

Filesystem contours читать из MAP/DEVELOPMENT/RESEARCH: source=`/srv/cripta/source_checkout`, runtime target=`/srv/cripta/runtime`, research target=`/data/cripta/research`; новые research writes — только на data-disk, runtime не зависит напрямую от research artifacts.

Patch/deploy не имеет права молча включать LIVE. Re-arm требует current LIVE-arm contract и explicit owner approval.

Dashboard presentation/read-model deploy отделён от trading runtime: static UI и
строго read-only projections/aggregations не требуют disarm/Execution OFF или
restart trading services; backend read-model может restart только Dashboard.
Auth/control/mutation/trading-decision code идёт через full runtime release.


## 7. Server-side scripts

Перед написанием/запуском server-side script/service/job, который пишет на filesystem или меняет effective actor, обязательно читать:
- `docs/CURRENT_PROJECT_MAP_RU*.md §1.4`
- `docs/DEVELOPMENT_RELEASE_RULES_RU*.md §5.1`
- `docs/DEVELOPMENT_RELEASE_RULES_RU*.md §19.1–19.4`

До mutation доказать exact actor/path/owner/group/mode/ACL/systemd sandbox.
Server-side script без actor/path contract: `PREPARED=NO`.

`ReadWritePaths=` не доказывает Unix write permission.
Проверка от root/SentinelX/другого user не доказывает права фактического writer.
Не лечить DENIED через `chmod 777`, uncontrolled recursive `chown/chmod`, запуск всего workflow от root или лишние privileges.

## 8. Git / deploy / runtime

Различать:
`REMOTE_HEAD`
`SOURCE_HEAD`
`INSTALLED_COMMIT`
`LOADED_COMMIT`
`OPERATIONAL_DELTA_COMMIT(S)` при наличии.

Source sync != deploy.
Commit != deploy.
Deploy != loaded runtime.
Service active != runtime behavior verified.

При operational deltas `SOURCE_LIVE_IDENTITY=PASS` для real-arm запрещён до сведения production state к одному exact verified release composition.
