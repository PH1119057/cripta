# Управление ресурсами Servercore

Контур заранее подготовлен, но реальные изменения заблокированы до установки API-реквизитов и read-only проверки доступных конфигураций.

API-ключ вводится только локально через `install-servercore-token.ps1`. Значение передаётся на сервер через stdin, хранится отдельно в `/etc/cripta/servercore.token` с правами `root:cripta 0640` и не попадает в аргументы процессов, HTML или журналы.

1. Установить OpenStack CLI в отдельную виртуальную среду.
2. Создать application credential с минимальными правами Compute read/resize/start/stop.
3. Заполнить `/etc/cripta/servercore.env`, права `0640`, секрет не выводить в веб и журналы.
4. Выполнить `readiness`, затем только read-only discovery сервера и flavors.
5. Проверить контрольные точки очереди и построить `plan`.
6. Изменение допускается только по точному `plan_id` и после явного подтверждения владельца.
7. После resize проверить ACTIVE, SSH, диски, БД, веб-службы и продолжение очереди.
8. Уменьшение ресурсов проходит по той же процедуре; готовые блоки не пересчитываются.

## Шлюз перед расходованием ресурсов

До повышения мощности обязателен сквозной smoke-test примерно на 10% одной репрезентативной монеты. Проверяются не только вычисления, но и финальные CSV/JSON, число строк, обязательные поля, контрольный блок, открытие результата и SHA256. Ресурсная аренда должна ссылаться на ID исследования, версию кода и SHA256 успешного smoke-test. Без этого увеличение ресурсов запрещено.

## Ресурсная аренда

Перед увеличением сохраняется фактическая исходная конфигурация сервера. Повышенные ресурсы привязываются к конкретной systemd-службе расчёта и маркеру полного результата. Автовозврат допускается только когда служба завершена и маркер результата существует. Возвращается сохранённая конфигурация, а не жёстко заданный тариф.

RAM выбирается после read-only discovery допустимых пар Servercore: минимальное разрешённое значение для выбранного vCPU, которое покрывает измеренный пик задачи с запасом. Фиксированные завышенные пары не являются правилом.

Текущая версия `apply` намеренно заканчивается блокировкой: провайдерский вызов добавляется только после проверки реальных endpoint, flavors и прав API.
