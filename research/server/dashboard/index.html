Готово · сервер и данные

  • Подключён отдельный SSD 150 ГБ, ext4, автоматическое монтирование в /data/cripta
  • Создана структура datasets / jobs / cache / staging / legacy
  • Скачан замороженный сегмент: 14 монет, 2534 файла, пропусков 0, ошибок 0
  • BTC и ETH отмечены индикаторами; остальные 12 — торговыми монетами
  • Настроен диск обмена K: — incoming, reports и logs
  • Развёрнут HTTPS-веб-интерфейс с авторизацией
  • Работают Nginx, PostgreSQL и системные службы Cripta

Готово · исследования и код

  • Старая линия сохранена в изолированной исторической библиотеке
  • Актуальный исходный код сохранён неизменяемым серверным релизом
  • Работают приём, проверка и очередь ZIP-пакетов исследований
  • Работает изолированный исполнитель с timeout и данными только для чтения
  • Сохраняются result.json, stdout.log и stderr.log; отчёты открываются через веб
  • Тестовый пакет прошёл queued → running → completed

Готово · связь с Bybit

  • Постоянный публичный WebSocket stream.bybit.kz для 20 торговых монет и двух индикаторов
  • Измеряется задержка matching engine → сервер и скорость JSON-декодирования
  • Mainnet API credential перенесён в зашифрованное системное хранилище
  • Авторизация api.bybit.kz подтверждена; доступны Order, Position и DerivativesTrade
  • Реальное исполнение заявок пока программно заблокировано
  • Долговечный read-only журнал: биржевые часы, баланс, позиции, заявки, свежесть потока и REST latency
  • Мониторинг свежести каналов, exchange truth, backup и резерва диска с историей переходов в PostgreSQL
  • Независимый монитор entered / shadow / blocked / skipped сигналов с MFE, MAE и first-hit уровнями

В работе · ближайший этап

  • Постоянный приватный WebSocket: orders / executions / positions / wallet
  • WebSocket Trade аутентифицирован; отправка команд остаётся заблокированной до испытаний
  • Безопасное закрытие позиции через reduceOnly
  • Горячее состояние заявок и позиций в PostgreSQL с обновлением через private WS
  • Телеметрия signal → send → accepted → filled

Осталось · до готовой рабочей платформы

  • Reconciliation REST → PostgreSQL при запуске и каждом переподключении private WS
  • Идемпотентный журнал команд: повторный idempotency key не создаёт вторую операцию
  • Разрешение неизвестного результата live-команды через exchange truth
  • Интерфейс открытия, отмены и закрытия заявки с подтверждением
  • Shadow / Testnet / Mainnet разделены независимыми серверными gates; разрешён только Shadow
  • Журнал команд и timings в PostgreSQL готов; ответы и fills появятся после испытаний Testnet
  • SHA256 и финальный manifest запустятся автоматически после завершения новых 1810 файлов
  • Ежедневная локальная копия проекта, PostgreSQL, конфигурации и отчётов с SHA256
  • Инструкция полного восстановления сервера и обязательная reconciliation-проверка
  • PostgreSQL backup восстановлен в отдельную тестовую БД и проверен по ключевым таблицам
  • Внешняя/off-site копия вне двух дисков этого сервера
  • Доверенный TLS-сертификат после привязки домена
  • После восстановления и проверки удалить временный NOPASSWD sudo
